# Yandex Tracker × Yandex Messenger: webhook-service

> Обезличенный проект прикладной backend-интеграции на Python + Flask. Это не бот и не скрипт: сервис связывал Yandex Tracker и Yandex Messenger вокруг рабочих задач. Идентификаторы, токены, персональные данные, URL и исходный код рабочего контура исключены.

## Контекст и задача

Строительная компания переходила от коммуникации в Telegram/WhatsApp к единой цифровой инфраструктуре. Yandex Tracker должен был стать единым источником учёта и контроля задач, но сотрудникам было важно сохранить привычный мобильный формат взаимодействия через мессенджер.

## Моя роль и вклад

- описал AS-IS / TO-BE, USER STORY, критерии приёмки и бизнес-правила;
- участвовал в настройке очередей, полей, досок, маршрутов и триггеров в Yandex Tracker;
- **самостоятельно разработал backend-интеграцию на Python + Flask**: endpoints для приёма webhook-событий, разбор JSON, извлечение полей задачи, статусов, вложений и служебных идентификаторов сообщений;
- обработал создание задачи, изменение статуса и добавление вложений; сервис направлял update в нужный чат или тред Yandex Messenger;
- организовал тестовый контур и проверял сквозные сценарии.

## Снабжение — один из реализованных бизнес-сценариев

`Инициатор → Снабжение → Финансы → Бухгалтерия → Контроль поставки`.

Этот маршрут показывает общий подход: backend-сервис передаёт контекст, статусы и вложения в привычный формат чата, а Yandex Tracker остаётся единым источником учёта и контроля.
